- **命令预览改「一行一个参数」+ 扩展参数多行输入（用户批注「优化命令预览和输入逻辑，调研互联网上单行单命令参数的结构」）**：出了什么事——服务页命令预览把整条命令挤成一段自动换行的长文本，参数一多就得在折行里找 flag；扩展参数输入框也只示意单行写法。**调研**：一行一个参数是业界主流惯例——llama.cpp 官方 README 的 llama-server 示例、Dockerfile 的 apt 安装、CMake/shell 脚本均以行拆参提升可读性与 diff 友好度；行尾续行符（`\`）是 bash 惯例、Windows cmd/PowerShell 各不相同，故**预览框作为只读查看器不带续行符**（逐行即等价 argv），复制按钮给出的仍是**单行可直接执行**的命令（跨 shell 安全）。**改法**：`shared` 新增 `formatCommandLines`（argv → exe 一行 + 每个 flag 连值一行、续行缩进两格，与 formatCommand 并列的纯展示函数——发射唯一实现仍是 buildArgv，无第二套规则）；`previewCommand` / `download:start` 式的 IPC 载荷改为**回传 argv 数组**，单行/逐行两种形态都由渲染层从同一 argv 格式化；扩展参数 placeholder 改多行示例（一行一个），提示文案说明「预览逐行展示、复制得到单行命令」——`tokenizeArgs` 本就按空白切分（含换行），多行输入无需改解析。**验证**：core +3（formatCommandLines 三态：配对缩进/引号/空 argv）、demo-mock 测试改 argv 契约；`pnpm lint` + 测试 + `pnpm e2e:web` 83 条全绿；mock 页实测预览逐行渲染、复制为单行。
