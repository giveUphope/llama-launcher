## Audit method (how to reproduce this list)

```bash
node scripts/style-audit.cjs      # or pnpm style:audit
```

13 checks are codified in `scripts/style-audit.cjs`; all green = consistent with the frontend.md §7.5 spec; ❌ findings print `file:line` detail and the script exits non-zero (so it can be wired into CI / pre-commit). What each check does:

1. bare colors inside components (token-only rule; `#fff`/`#1a1a1a` allowed only as text on colored buttons)
2. bare font sizes inside components (must go through `--fs-*`)
3. radii go through tokens (`2px` track / `50%` circle / `0` are the exceptions)
4. spacing scale (gap ∈ 4/5/6/8/10/12/14, `0` allowed; **there is no 1/2/3px micro-spacing tier — it always normalizes up to 4px**, see #16)
5. no duplicated scoped button classes (only the globally converged `action-btn`/`mini-btn`/`tab-btn`; component-specific classes such as `modal-btn`/`dl-btn`/`fb-btn`/`win-btn` may keep scoped styles, see §7.5.5; `ctrl-btn` disappeared along with "button text inlined", see #27)
6. shadows/overlays go through `--shadow-*` / `--overlay`
7. inventory of `backdrop-filter` usage sites (prints the list for manual review — is it limited to the glass layers / modal backplates allowed by §7.5.6? dropdowns and menus are solid now, see #41)
8. animation only touches transform/opacity (transitions on layout properties must carry `var(--dur-*)`)
9. semantic line heights (1 / 1.3 / 1.4 / 1.5 / 1.55 / 1.6; `normal` / `var()` pass through)
10. font weights restricted to 400 / 600 / 700 (`normal`=400 / `bold`=700 accepted as equivalents)
11. top-level selectors in non-scoped `<style>` blocks (a `<style>` without `scoped`) must contain at least one component-private class — never Arco global class names alone, otherwise a popup teleported to body hits other components globally (§7.5.6)
12. do not override Arco internal state classes (`.arco-*-checked` / `-active` / `-selected` / `-disabled` / `-current` / `-dragging` / `-expanded`) — they are brittle across Arco upgrades; express selected states through Arco's own states or the `color` prop instead
13. `a-progress`'s `:percent` must be a **0–1 ratio** — Arco's `line.js` renders `width: percent * 100 %`, so passing a percentage (any expression containing `* 100` or a `Pct`-style name) pins the bar to full; in practice this is exactly the "download progress bar doesn't match the real progress" symptom (#71)

### 56. Selected row in the model table lost its color on hover (Arco's row-hover rule outranked the selected background) — 🟢 Fixed (2026-09-13)

- **Location**: `packages/ui/src/components/models/LocalModelsPanel.vue` (`:deep(.arco-table-tr.row-selected > td)` inside `.models-table`).

- **Verification**: `pnpm style:audit` all green; on the mock page (`127.0.0.1:5173/#/models`) hovering a selected row in either theme keeps the computed `td` background at `rgb(var(--primary-1))` (dark `rgb(0,13,77)` / light `rgb(232,243,255)`) instead of falling back to `--color-fill-1`.

### 57. Dark-theme selected row background was too dark (primary-1 resolves to a near-black navy; filling a whole row looks heavy) — 🟢 Fixed (2026-09-13)

### 58. Status tags passed semantic color names that Arco doesn't recognize to a-tag (success/warning/danger/processing) — 🟢 Fixed (2026-09-13)

- **Location**: `StatusTag.vue` (the `arcoStatus` map), `StatusBar.vue` (the `statusColor` map + the two "Copied" feedback tags).

### 65. Style defects found by real-render inspection (dark single-class badge suppressed by Arco / list row padding reset never applied / demo-mock data drift) — 🟢 Fixed (2026-09-18)

- **Location**: `DownloadCard.vue` (`.info-tag` / `.rec-badge` / the `:deep(.arco-list-item)` of `.result-list` / `.file-list`), `packages/ui/src/dev/demo-mock.ts` (`download.listFiles`).

## 🟢 Confirmed design decisions (formerly the "to confirm" items — no change needed)

- ~~**mini-btn default text color** **`--fg-secondary`**: inline mini buttons used the secondary text color (to distinguish them from `action-btn`'s `--fg-primary`), which fits the "mini = secondary inline action" semantic tier; confirmed and kept (frontend.md §7.5.5).~~ **[Re-checked 2026-09-20: obsolete]** — `mini-btn` and `--fg-secondary` both hit 0 times in `packages/ui/src`: once every button had moved to a-button the custom class was deleted (§7.5.5), so this survives only as a historical decision record.

- **Filter chip radius**: filter chips such as DownloadCard's use the pill `--radius-pill` (the filter-tag semantic), fixed into frontend.md §7.5.3's radius system. **Note (2026-09-18)**: that radius is a business convention, not an Arco default (a-tag's default `--border-radius-small` is 2px); since 2026-09-18 a chip's hover/selected state is handed back to Arco's own state (`color="arcoblue"`) with no `.arco-tag-checked` overrides. Also note: this entry's original "container cards use `--radius-card` (16px)" is obsolete — that token went away with #20's section-divider style / #22's cleanup, section cards are now `border-radius: 0`, and radii survive only in **three tokens — pill / row / control** (`theme.scss:33-35`, all 4px; `--radius-modal` no longer exists) + the 2px track + 50% circles.

- **Colored mini-badge box model**: the download card's `--badge-*` colored mini badges are all carried by `a-tag size="small"` + `1px 6px` padding + `--radius-pill` radius (§7.5.4 ①).

- **Two list row variants**: native rows (`a-list` defaults, e.g. PresetsPanel) and compact selectable rows (`:split="false"` + the row container supplying border/padding/selected background, e.g. DownloadCard, FileBrowserModal) coexist; **a third variant is forbidden** (§7.5.7).
- **Badge palette hue budget**: download badges split into three families — category (4 colored values), quantization (8 colored values), source (**neutral**, taking no hue). The hue budget is spent on the first two families, so any color the source family takes is bound to collide with an attribute badge on the same row (originally `--badge-src-huggingface` and `--badge-quant-k` were both `#2563eb`); hence sources are always neutral and distinguished by text. Category and quantization do have adjacent hues (`cat-gguf` purple ↔ `quant-i` violet, `cat-safetensors` green ↔ `quant-fp16` green), judged acceptable because the two families sit in fixed positions and **always carry text labels** (`GGUF` vs `Q4_K_M`); hue orthogonality is not pursued.
