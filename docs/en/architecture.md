## 1. Project overview

llama\_launcher is a desktop launcher for the `llama-server` binary of llama.cpp. It can: pick `.gguf` models, read GGUF metadata to derive suggested parameters automatically, configure 60 startup parameters, start/stop/restart the service, watch output live, save/load presets, download models online, and switch between light/dark themes and Chinese/English. The app does not bundle the llama.cpp binary — the user selects the directory holding llama-server and the executable is auto-detected.

There is only one actively maintained line today: `apps/desktop` + `packages/*` (Electron + TypeScript + Vue 3 + Vite + Pinia). The whole project is managed with pnpm workspace + turborepo, and every build artifact is orchestrated by turbo.

## 3. Monorepo architecture

4 packages in total, with dependencies flowing in one direction:

| Package                     | Version | Responsibility              |
| ------------------------- | ----- | --------------------------- |
| `@llama-launcher/desktop` | 0.0.47 | Electron main process + preload + packaging |
| `@llama-launcher/core`    | 1.0.0 | Core business logic (process/command/scan/download/GGUF)    |
| `@llama-launcher/shared`  | 1.0.0 | The single source for type definitions, the param table and i18n         |
| `@llama-launcher/ui`      | 1.0.0 | Vue 3 + Vite + Pinia frontend     |

**Dependencies:**

```
desktop → core + shared
core    → shared
ui      → shared
```

- `shared` is the **single source of truth** for type definitions, the param table and i18n; both `core` and `ui` depend on it, which avoids duplicate definitions.

- `desktop` does not depend on `ui` directly — it loads `ui`'s static assets at runtime through `extraResources` / build artifacts.

- **pnpm workspace** manages the local package links (`workspace:*`), and **turborepo** orchestrates the `build` / `lint` / `test` / `dev` tasks.
