# Development workflow

> Language: English · [中文](../zh/workflow.md)
> Scope: Development workflow: build, typecheck, testing, packaging, docs maintenance and documentation-writing conventions (including the Chinese/English two-tree pairing rules).
> Index: [README.en.md](../../README.en.md) · Related: [architecture.md](architecture.md) · [packaging.md](packaging.md)

| Command | Description |
|------|------|
| `pnpm dev` | Start dev mode (`scripts/dev.cjs` three-process orchestration, not routed through turbo) |
| `pnpm build` | Build all packages |
| `pnpm test` | Run the tests |
| `pnpm lint` | Typecheck + IPC sync verification (`verify-ipc-sync.cjs`) + three-way param cross-check with dictionary/count validation (`verify-params-sync.cjs`) + version declaration consistency (`verify-version-sync.cjs`) + docs link check (`check-docs-links.cjs`, also runnable on its own as `pnpm docs:check`) + Chinese/English tree pairing check (`verify-doc-pairs.cjs`: both twins exist / language line present / structure and version strings match) + six i18n checks (`verify-i18n-usage.cjs`) + oxlint (`pnpm lint:ox`) |
| `pnpm dist` | Package the single-file Portable build (one command at the repo root, delegating to `@llama-launcher/desktop dist`; electron-builder, output `release/*.exe`, automatically falling back when the output directory is locked) |

Dev-mode hot reload is orchestrated by `scripts/dev.cjs` over three processes: the Vite dev server (UI HMR) + `tsc -b --watch` (incremental rebuilds of shared/core/desktop) + `scripts/dev-watch.cjs` (watches main-process dist / preload sources / shared types, and on a change it regenerates the preload and restarts Electron automatically — `LLAMA_DEV_SKIP_QUIT_KILL=1` keeps a hot restart from taking the dev session tree down with it). Changes to UI components/styles hot-update instantly; changes to core/shared/main-process/preload code trigger an automatic rebuild and restart, with no manual step. Exit semantics: whichever task exits first ends the whole session with its exit code, and the remaining tasks are cleaned up process-tree style with `taskkill /T /F` (the user closes the window → dev-watch exits 0 → vite/tsc are swept along with it, no port left behind).

**Why not turbo / concurrently / a nested `pnpm` inside a subcommand**: on Windows all of those go through the `.cmd` batch shims in `node_modules/.bin`, and when cmd.exe receives Ctrl+C while a batch file is waiting on a child process it prints `Terminate batch job (Y/N)?` and blocks on a keypress — the old chain stacked 4 batch layers, so one Ctrl+C could not get out (you had to press it twice, and turbo still waited out its graceful timeout before `Force killed Turborepo tasks`). All three tasks in `dev.cjs` are executed directly by node against the real JS entry that the dependency's `package.json` `bin` points at: zero batch layers, one Ctrl+C is enough. New dev tasks must keep the same style.

## Dependency maintenance (recurring evaluation entry point)

Evaluate dependency freshness periodically with the commands below (this repository goes through the npmmirror mirror):

```bash
pnpm outdated -r                 # which dependencies can be updated (-r covers all 5 workspace packages)
pnpm install --frozen-lockfile   # check that the lockfile is in sync with package.json (CI enforces this mode by default)
```

**Upgrade flow**: change the version declaration in `package.json` → `pnpm install --no-frozen-lockfile` (refreshes the lockfile) → `pnpm lint` + `pnpm test` + `pnpm build` all green → then `pnpm install --frozen-lockfile` to re-verify → update `docs/CHANGELOG.md [Unreleased]`.

**Current boundary (2026-09-01)**: TypeScript is pinned at `^6.0.3` — TS 7.0 (native Go) has no stable programmatic API (7.1 provides one) and the latest `vue-tsc` still crashes (`./lib/tsc` is no longer exported; the upstream fix vuejs/language-tools#6123 is unreleased). Triggers for upgrading to `^7`: ① npm publishes a `vue-tsc` that contains #6123, or ② the TypeScript 7.1 stable API lands and vue-tsc adapts to it; at that point also re-evaluate whether to keep `--no-daemon` (turbo 3.0 is not released yet — how that flag is handled follows the official notes after its release).

## Documentation-writing conventions

Every document under `docs/` follows one shared authoring logic and format (keep new or edited documents consistent with it). The repository root holds **two paired landing pages, one per language**: [README.md](../../README.md) (Chinese — the page GitHub renders by default when a visitor opens the repository) and [README.en.md](../../README.en.md) (English, reached from the language line on top of the Chinese page), each keeping only eight blocks — "What it takes off your plate / Highlights / Quick start / How you use it / Project layout / Tech stack / Documentation map / License" — while all in-depth detail is pushed down into `docs/`; inside `docs/` the content splits by language into two trees — `docs/zh/` (the authoritative Chinese version) and `docs/en/` (the English mirror) — matching one-to-one by name and structure:

1. **Title**: `# Document title`, one sentence that summarizes the topic.
2. **Note block**: three lines follow immediately under the title — the first is the **language line**: the Chinese side writes 「语言：中文 · 」plus an English link to the same-named file under `../en/`, the English side writes "Language: English · " plus a 中文 link to `../zh/` (inside a `docs/*/` subdirectory the depth is one level greater, so change the prefix to `../../zh/`; these two are described in words on purpose, since a bracket link example written here would be parsed by `check-docs-links.cjs` and judged broken). The second line is `> Scope: <what this document covers>`, the third line is `> Index: <relative link to the README> · Related: <relative links to related documents>`. The language line is the visible entry point of the bilingual pairing — without it, English readers simply cannot get in.
3. **Section numbering**: keep the numbering the architecture documents already use (`N.x`); write cross-document references as "<document name> §N.x" or as relative links, and never renumber a section (that keeps link anchors stable). **Both trees keep the same set of numbers**, so that "frontend.md §7.5.4" holds in either language.
4. **Consistent terminology**: terms such as parameters / presets / packaging match `AGENTS.md` and `docs/zh/params/LLAMA_SERVER_PARAMS.md`.
5. **Links**: inside docs/ always use relative paths (`frontend.md`, `style/STYLE_TODO.md`); **when pointing at a sibling document, point only into the same-language tree** (English documents link `docs/en/*`, Chinese documents link `docs/zh/*`); for untranslated historical content such as `docs/CHANGELOG.md` and `docs/archive/**` both trees share the same path; code paths go in backticks (e.g. `packages/ui/src/styles/`); the relative links and anchors of README.md / README.en.md and AGENTS.md are validated by `scripts/check-docs-links.cjs` (`pnpm docs:check`). **An English document must not carry over a `#anchor` produced by a Chinese heading** (the English heading slug differs) — drop the anchor and keep only the file link.
6. **Direction of bilingual sync**: change the Chinese version first, then sync the English mirror; **touching only one side counts as unfinished**; a new document must be created in both trees at once. Numeric claims (total parameter count, channel count, group count, measured pixels and milliseconds) must be equal across the two trees — `verify-ipc-sync.cjs` and `verify-params-sync.cjs` already scan both trees recursively, and the English form ("57 channels") is checked just like the Chinese form (`「57 个通道」`), so dropping one side while translating fails on the spot. **Structural pairing is hard-gated by `verify-doc-pairs.cjs`** (wired into `pnpm lint`): the same-named file must exist on both sides, the language line must point at a real counterpart, and the heading count / `N.x` numbering sequence / table-row count / fence count / list-item count / set of `x.y.z` version strings must all be equal. It **deliberately does not compare whole-file number multisets** — Chinese 「收尾二批」 rendered as "batch 2", or 「退出码非 0」 rendered as "exits non-zero", is a difference of language rather than of content, and a gate that fails on those gets weakened or bypassed instead of obeyed. What still cannot be caught is **a paragraph translated away under an unchanged structure**, so that part stays a manual check; numbers that record a historical measurement (e.g. the static audit had 12 checks at the time) are kept exactly as the Chinese side wrote them rather than refreshed to today's value.
7. **Do-not-translate list**: `docs/CHANGELOG.md` (release history), `docs/archive/**` (read-only archive), `docs/params/llama-server-help-out.txt` (the language-independent help baseline) and `docs/badges/` stay single copies with no `en/` mirror; both gates skip them accordingly.
8. **Provenance**: sections split out of the original CODE\_WIKI.md keep their content as-is (only the formatting was adjusted); newly added content is dated; things to fix / known issues are registered in `style/STYLE_TODO.md` (one copy per language) instead of being scattered through the body text.
9. **Exceptions (they keep their own format)**: `docs/CHANGELOG.md` (release history, grouped by version) and `docs/{zh,en}/params/LLAMA_SERVER_PARAMS.md` (written by `scripts/generate-params-doc.cjs` — **both languages in a single run**; do not hand-edit either side).
10. **Writing style**: see the "表述风格" (Writing style) section of [AGENTS.md](../../AGENTS.md) — say what happened first and only then the technical details; a solution must state three things (which file/location to change / why here and not elsewhere / how to verify it afterwards); for flows and state machines prefer a Mermaid diagram over an arrow chain described in words.
