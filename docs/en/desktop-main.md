# Electron main process

> Scope: the Electron main process: entry point, window management, IPC registration, the Launcher bridge, preload.
> Index: [README.en.md](../../README.en.md) · Related: [ipc-channels.md](ipc-channels.md) · [core-modules.md](core-modules.md)

### 6.1 Entry point (main/index.ts)

- **Single-instance lock**: `requestSingleInstanceLock` stops a second copy from starting; when the app is launched again, the existing window is focused.
- **`whenReady`**: install the network transports (`installHfTransport()` + `installDownloadTransport()` — the Electron `net` stack avoids hf-mirror.com rejecting the BoringSSL TLS fingerprint, see [core-modules.md](core-modules.md) §4.6) → register IPC → create the window → set up `launcherBridge`.
- **`before-quit`**: `launcherBridge.disposeSync()` (synchronous force-stop: `forceStop` + process-tree sweep) guarantees the child process is stopped so nothing is left behind — the quit path cannot await asynchronous cleanup.
- **External links** open in the system browser (`http://` / `https://`).

### 6.2 Window management (window.ts)

- **Default size**: 1280×800, minimum 1024×680.
- **Frameless window**: `frame: false` with a custom title bar (TopBar `win-btn`); the window maximizes automatically on startup; window icon `resources/icon.ico`.
- **Window geometry persistence**: stored as `x,y,width,height`, with the legacy `WxH` format still accepted.
- **Debounced save**: 500ms debounce so dragging a resize handle does not hammer the disk.
- **Security configuration**: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: false`.
- **Dev-mode test**: `NODE_ENV=development` or `!app.isPackaged`.
- **Hot-reload escape hatch**: the `LLAMA_DEV_SERVER_URL` environment variable points at the Vite dev server, so even a production build can attach to a local frontend.

### 6.3 IPC registration (ipc/index.ts feature-domain registry)

IPC is registered declaratively per feature domain: each module under `ipc/` — settings/models/presets/server/logs/system/window/download — exports a `register*Ipc` function, and `ipc/index.ts` assembles them into the `ipcRegistrars` array (`registerIpcHandlers()` iterates and calls them); the shared model-directory watcher singleton lives in `ipc/models-watcher.ts` (`watchModelsDir`/`notifyModelsChanged`).

57 IPC channels in 10 categories: Settings / Models / Presets / Server / Logs / General /
 Window / System / Download / FS.

- When a download completes, `notifyModelsChanged()` is called to refresh the model list.
- **Language sync for main-process text**: the `settings:save` handler calls `setLang(s.language)` after writing settings (see `ipc/settings.ts`), so instant strings the main process produces with `tr()` (probe failure reasons, tray menu) follow the language switch without a restart; the tray menu takes effect immediately because it is built fresh on every right-click (§6.8).
- `models:watch` watches `.gguf` file changes recursively and notifies the renderer process after a 500ms debounce.
- `system:findLlamaExe` looks for `llama-server.exe` in the given directory (including one level of subdirectories); used for inline detection.
- `system:estimateVram` / `system:estimateModelFit`: VRAM probing (spawns `llama-server --list-devices`) plus the GGUF KV memory model — estimates usage on both sides (VRAM and RAM), the OOM-free context ceiling, performance-target linked suggestions and the model-fit verdict (delegated to core `devices.ts` / `vram-estimate.ts` / `target-recommend.ts`). **The 30s shared device-probe cache stores successful results only** — on failure `at` is reset to zero, so once the user points the engine directory back at a valid one the next call re-probes immediately (the old implementation cached the empty result too, so even after fixing the directory it kept idling for half a minute); the probe failure reason (including the paths that were tried) comes back on the result's `probeError`, and the "VRAM usage" tooltip on the Params page shows it directly instead of leaving just a "—"; that text is generated by `tr()` in the current language (the main-process language is synced via `setLang` inside `IPC.SETTINGS_SAVE`, see `ipc/settings.ts`) and must never be a hardcoded Chinese literal — bare Chinese fails `verify-i18n-usage.cjs`. **The probe exe is resolved by core's `resolveServerExe`** (settings → same directory → `llama_dir` and its first-level subdirectories → dev-mode default, each candidate existence-checked), so renaming or moving the engine directory falls back automatically instead of failing silently. Results are cached for 60s keyed by model|dtype|target|ngl|ctxSize.
- `system:benchLlamaRun` / `system:benchLlamaStatus` / `system:benchOnStatus`: the llama-bench offline health check (state transitions are pushed by the main process; status is read only to resync when the tab becomes visible) (pp512/tg128, one job per model + status polling, delegated to core `llama-bench.ts`).
- **Close-behavior chain**: window close requests all go through `app-exit.ts`, which branches on the `close_behavior` setting (`ask`/`exit`/`tray`); on `ask` the main process sends `window:showCloseDialog` to the renderer, which answers via `window:closeDialogResult` (a 10-second timeout falls back to **minimizing to the tray**, so no data is lost), and a running service adds a second confirmation.

### 6.4 Launcher bridge (launcher-bridge.ts)

- **Singleton** `launcherBridge`: every window shares the same Launcher instance.
- **Output buffer**: capped at 5000 entries; when a new window connects the historical output is replayed (in chunks of 200 lines) so state stays visible; output is **aggregated into one batch over a 16ms window and delivered in a single message** (`SERVER_OUTPUT_BATCH`, payload `OutputEntry[]`). Before this, lines were still sent one by one even after aggregation — during model loading, hundreds of lines meant hundreds of IPC calls plus structured clones plus hundreds of renderer refreshes, which measurably blocked the renderer process; the renderer-side entry point is `pushOutputBatch()` in the `server` store (one batch enqueued + one trim).
- **Cleanup**: `disposeSync()` (synchronous force-stop, for `before-quit`) / `dispose()` (asynchronous, waiting for `exit` or a 5-second timeout).
- **Restart race avoided**: while running, `Launcher.restart()` does `proc.once('exit', () => start)`, waiting for the old process to exit before starting the new one (when not running it starts directly). This avoids the false `Server is already running` produced by a manual stop() immediately followed by start(), where `launcher.proc` still points at the old process (taskkill kills asynchronously, and proc is not nulled before the exit event fires).

### 6.5 Preload (preload/index.cjs)

- **CommonJS module**: Electron requires preload scripts to be CommonJS (independent of `sandbox: false` — ESM syntax cannot be loaded in the preload environment at all).
- **`contextBridge.exposeInMainWorld('api', api)`**: exposes a safe API to the renderer process.
- **Generated IPC constants**: preload cannot import from shared, so the IPC channel constants are generated by `scripts/generate-preload.cjs` from `shared/src/types/ipc.ts` into the sibling `ipc-constants.cjs` (`pnpm generate:ipc`), which `index.cjs` requires; `verify-ipc-sync.cjs` checks that the generated file is not stale and rejects hand-inlining the constants back into `index.cjs`.
- **`clonePlain` serialization**: every argument is serialized through clonePlain before being passed, keeping the cross-context transfer safe.

### 6.6 Exit behavior (app-exit.ts)

The single entry point for closing the window / quitting, branching on the `close_behavior` setting (`ask`/`exit`/`tray`):

- **`handleWindowClose(win)`**: `tray` → `minimizeToTray(win)` (hide the window, keep the processes alive); `exit` → `requestExit(win)`; `ask` → show the in-app CloseDialog (one request, one answer), where "remember my choice" optionally gets written to settings, and a timeout or a failed reply falls back to minimizing to the tray.
- **`requestExit(win)`**: while the model service is running, a second confirmation is shown first (`exit-confirm`, defaulting to cancel on timeout so the service is not stopped by mistake); after confirmation `app.quit()`, and child processes are cleaned up synchronously during `before-quit`.
- **Request/response mechanism**: once the main process intercepts the `close` event it sends the request over `IPC.WINDOW_SHOW_CLOSE_DIALOG` (`CloseDialogRequest { id, mode }`), the renderer shows the dialog and replies over `WINDOW_CLOSE_DIALOG_RESULT` (forwarded by `handleCloseDialogResult`); when the window is unusable or the renderer does not respond, the 10-second timeout covers it — there is no fallback to the native dialog. The `quitting` flag prevents the quit request from being intercepted by `close` in a loop.

### 6.7 Window↔process association registry (process-registry.ts)

`ProcessRegistry` (singleton `processRegistry`) maintains a `windowId → set of child processes associated with that window` map, so that exactly that window's llama-server processes are cleaned up when the window closes or the app exits:

- **`associate(win, proc, exeName)`**: records the association (deduplicating the same process instance to avoid repeated taskkill).
- **`cleanupWindow(win)`**: performs a **two-phase termination** on the associated processes (`terminate()` first for a graceful exit — SIGTERM / taskkill without /F, escalating to a force-kill if they have not exited after the timeout); only when a PID-targeted kill cannot confirm the process is dead does it fall back to sweeping by exe name (`sweepByName`), which avoids killing the user's own llama-server of the same name. Idempotent, and the mapping is removed after cleanup.
- **`cleanupAll()`**: the exit safety net, cleaning up processes associated with every window.
- Extensible across windows: the product is single-window today, but the registry naturally supports several windows each managing its own processes. Every cleanup step is recorded through `cleanupLogger` (see [core-modules.md](core-modules.md) §4.12).

### 6.8 System tray (tray.ts)

The keep-alive implementation that parks the app in the tray once the window is hidden (active when `close_behavior='tray'`, or when the exit prompt answers "Minimize to tray"):

- **`createTray(win)`**: two menu items (Show Main Window / Quit — Quit goes through `requestExit`, with a second confirmation while the service is running); the template is provided by `buildTrayMenu(win)` and is **built fresh on every right-click**, so language switches take effect immediately (the tray itself is created only once — caching the menu at startup would leave it stuck in the old language until the next restart; the language itself is synced by `IPC.SETTINGS_SAVE → setLang`).
- **Icon**: 32px PNG preferred (it renders reliably at every Windows tray DPI), falling back stepwise to 16px PNG / icon.ico; two path sets, one for dev and one for the packaged app (`extraResources`).
- **Right-click menu placement**: the native Windows `setContextMenu` expands downward from the mouse position (it never flips up on its own), so right-click now calls `popUpContextMenu` manually — the bottom edge of the menu aligns with the top edge of the icon and the right edges align, clamped to the display's work area, falling back to below the icon when there is no room above; the height is estimated item by item from the template (item 33px / separator 7px / border 4px).
- Single click on the tray icon: show and focus the main window.
